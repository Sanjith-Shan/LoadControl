# LoadControl numbers

Every figure here comes from a run in `results/*.jsonl`. Each run records its
configuration, the per-second series, LoadControl's Prometheus counters, the
fault timeline, container restarts, and the machine and its load (VM CPU every
second, host CPU every 2 s, busy processes, other containers, and whether the
other project sharing the machine held the bench lock). The tables after the
headline list are generated by `bench/lcnumbers.py` and average clean runs
only (rule in `clean()`: no peer lock, no restart, host not busy with other
work). `n` is the number of clean runs behind a row.

**Say these first.** One mini PC (AMD Ryzen 3 4300U, 4 cores, 16 GB, Windows
11). The benchmark runs in a WSL2 VM with 2 vCPUs and 6 GB, and the load
generator runs inside the same VM, so it competes with the services. The
machine was shared with another project's build for part of the day; runs
that overlapped with it are flagged and were repeated. DeathStarBench
hotelReservation, pinned commit, request mix from its own wrk2 script. Goodput
means 2xx responses within 500 ms, counted once per user request. Capacity is
small (about 400 req/s) because the whole microservice graph shares two vCPUs.
Most configurations have 1 to 3 runs; the run-to-run spread near the capacity
cliff is large (e.g. 360 and 412 good/s at the same 450 req/s offered).

## What is not quotable

- Anything as a production number: this is one small VM.
- The first exp1 round's rate-limit collapse at 3x (148 req/s) and dips at
  1.5x: those runs overlapped with other work on the host (BUG_LOG B8). The
  clean repeats are in the tables.
- `exp3_coldcache_only.jsonl`: its MongoDB latency fault never reached the
  services (BUG_LOG B3); only its cache flushes were real.
- `results/invalid/`: exp4's first round, whose fault did nothing.
- The plain (unweighted) CPU hog runs (`*-hog`): one busy thread barely
  changed anything, so they show that trigger was too weak, not resilience.
- Single-run figures (rows with n = 1) are indications, not distributions.
